# LoreSpec への拡張のルール

LoreShelf は、LoreSpec(`LORE.md`)に沿って作ります。
LoreSpec だけでは足りない場面が出たときに、**どう拡張するか**を決めておくための文書です。
拡張を足す前に、必ず、この文書の条件に照らします。

**現在、採用している拡張は、ありません。**

## 基本の方針

1. **LoreSpec に沿う。** LoreShelf は、純粋な LoreSpec のファイルを、いつでも読めます。書き出すときも、既定では、純粋な LoreSpec で書きます。
2. **拡張は、必要になってから足す。** 「あったら便利」では足しません。
3. **拡張しても、元のファイルとの互換を壊さない。** 拡張の項目は、なくても読めます。
4. **元の LoreSpec の文章は、書き換えない。**

LoreSpec は MIT ライセンスで、改変も再配布もできます(著作権表示とライセンス文を残すことが条件です)。
ただし、書き換えた文章を「LoreSpec」の名前のまま出すと、公式と混同されます。
拡張は、別の名前(LoreShelf Extensions)で、元の文章とは別のファイルに書きます。

## 拡張を足してよい条件

**次の6つを、すべて満たすときだけ**、拡張を足します。

1. **実際の失敗が、記録にあること。** 何が起きたかを、LORE(または、日付つきのメモ)に書いてある。
2. **LoreSpec の既存の仕組みで、表せないこと。** タグ、本文、`domains`、`trails`、`Connections` で代用できる場合は、代用する。代用のほうが明らかに悪いときだけ、拡張を考える。
3. **後方互換であること。** その項目がないファイルも、これまでどおり読める。その項目を知らない他のツールが、無視しても壊れない。
4. **名前空間を分けること。** 拡張の項目の名前には、接頭辞 `x-loreshelf-` を付ける(例: `x-loreshelf-version`)。将来、LoreSpec が同じ名前を使っても、ぶつからない。
5. **拡張に、独自のバージョンを付けること。** `lorespec: "0.1"` はそのままにして、拡張の版は別に数える(最初は `0.1`)。
6. **変更履歴に、理由を書くこと。** いつ、何を、なぜ足したか。

## 提案の書き方

拡張を足したいときは、`docs/extensions/` に、1拡張につき1ファイルで、次の形で書きます。
(まだ1つもありません。最初の提案を書くときに、フォルダを作ります。)

```
# 拡張の提案: 〔名前〕

- 状態: 提案 / 採用 / 却下
- 日付: 〔YYYY-MM-DD〕

## 起きた失敗(根拠)
何が、いつ、どのファイルで起きたか。記録(LOREのIDなど)へのリンク。

## 既存の仕組みで代用できないか
タグ、本文、domains、trails、Connections で試したこと。なぜ足りないか。

## 提案する内容
項目の名前(x-loreshelf-…)、型、取りうる値、書く場所。
書き方の例を、1つ以上。

## 互換性
この項目がないファイル、この項目を知らないツールで、何が起きるか。

## 却下したほかの案
```

## 元の LoreSpec との関係

- 自分のフォーク(`LoreSpec-Manager`)は、**元と同一のまま**にしておきます。元の更新を、そのまま取り込めるようにするためです。
- 元に提案したくなったときは、そのフォークから、PR(または issue)を出します。元の LoreSpec のリポジトリは、issue と PR を歓迎しています(2026-10-08 時点で、更新は 2026-04-22 から止まっています)。
- 拡張の文書は、**当面、この LoreShelf のリポジトリの `docs/` に置きます。** リポジトリが増えると、維持の手間も増えるためです。拡張が育ってきたら、フォークへ移すかどうかを、そのときに決めます。

## 拡張の候補(まだ作りません)

これまでに出た困りごとのうち、将来、拡張になりうるものです。**根拠が足りないので、いまは、メモだけです。**
上の条件の1(実際の失敗の記録)を満たしたものから、順に、提案を書きます。

| 候補 | 根拠 | 現在の代用手段 |
|---|---|---|
| バージョンの欄 | ゲームなどの版で事実が変わる。会話の日付では、版が分からない | タグ(対象とバージョンを1つにしたもの)と本文。`docs/PROMPTS.md` の6節 |
| 著者の欄 | ゼミで、誰のLoreかを残したい(まだ試していない) | なし |
| 言語の欄 | 日本語と英語で、検索が分かれる | なし |
| 系譜(lineage) | 文脈を実際に引き継いだ関係を、意味的な近さとは分けたい | 本文と Connections |
| オブジェクトの書き方の固定 | 公式の例と、AIの出力で、書き方が違う | 読み取る側が、複数の書き方を受け入れる |
